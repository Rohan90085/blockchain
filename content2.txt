Definition:
A public function or variable can be accessed from anywhere (inside the contract, derived contracts, and outside contracts).
Extra Points:
Default visibility for state variables is public.
Public variables automatically create a getter function.
Can be called internally and externally.
Most commonly used for functions that need to be accessed by users.
Example:
Solidity
Copy code
pragma solidity ^0.8.0;

contract Test {
    uint public num = 10;

    function getNum() public view returns(uint) {
        return num;
    }
}
Key Points
Accessible everywhere
Auto getter for variables
Can be inherited
2. Private
Definition:
A private variable or function can only be accessed inside the same contract.
Extra Points:
Not accessible in derived (child) contracts.
Used for sensitive internal logic.
Even though private, data is still visible on the blockchain (not truly secret).
Example:
Solidity
Copy code
pragma solidity ^0.8.0;

contract Test {
    uint private num = 5;

    function getNum() public view returns(uint){
        return num;
    }
}
Key Points
Only inside the contract
Not inherited
Used for internal logic
3. Internal
Definition:
An internal function or variable can be accessed inside the contract and in derived (child) contracts.
Extra Points:
Similar to protected in other languages.
Useful when building inheritance-based smart contracts.
Cannot be accessed from outside contracts directly.
Example:
Solidity
Copy code
pragma solidity ^0.8.0;

contract Parent {
    uint internal num = 20;
}

contract Child is Parent {
    function getNum() public view returns(uint){
        return num;
    }
}
Key Points
Inside contract
Derived contracts
Used in inheritance
4. External
Definition:
An external function can only be called from outside the contract.
Extra Points:
Cannot be called directly inside the contract.
Can be called internally using this.functionName().
Gas efficient when receiving large arrays.
Example:
Solidity
Copy code
pragma solidity ^0.8.0;

contract Test {

    function show() external pure returns(string memory){
        return "Hello";
    }
}
Key Points
Only outside contract
Cannot call internally directly
Gas efficient

An interface in Solidity is used to define the structure of functions that other contracts must implement.
Points
Contains only function declarations (signatures).
No function implementation (body).
Used to interact with other smart contracts.
Similar to interface in Java.
Helps in standardizing communication between contracts.
Rules of Solidity Interface
Functions must be external.
No function body (only declaration).
Cannot declare state variables.
Cannot have constructors.
Interfaces cannot inherit normal contracts (only other interfaces).
All functions must be implemented in the contract that uses the interface.
Example
Solidity
Copy code
//SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

interface Student {

    function create(uint id, string memory name) external;

    function remove(uint id) external;

}

contract student is Student {

    mapping(uint => string) public list;

    function create(uint id, string memory name) external override {
        list[id] = name;
    }

    function remove(uint id) external override {
        delete list[id];
    }
}
Explanation
Interface Student
Defines two functions:
create() → add student
remove() → delete student
Contract student
Implements the interface
Uses mapping to store student data
Uses override keyword because it implements interface functions
Extra Points (Important for Exams)
Interfaces are mainly used for cross-contract communication.
Used heavily in DeFi and ERC standards.
Example:
ERC‑20 Token Standard
ERC‑721 NFT Standard
These standards are defined using interfaces.
✅ Short Definition (for exam)
An interface in Solidity is a contract-like structure that contains only function declarations without implementation and is used to interact with other smart contracts.
